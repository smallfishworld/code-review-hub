# Spec Delta

## Purpose

评审任务完成后主动推送结果通知：支持邮件渠道与企业私有聊天软件的聊天机器人（webhook）渠道，渠道与触发规则可配置，通知失败不影响评审任务本身。

## ADDED Requirements

### Requirement: 邮件通知渠道

系统 SHALL 支持配置邮件通知渠道，包括 SMTP 服务器地址、端口、发件账号与凭据、收件人地址列表。凭据 SHALL 加密存储且界面回显不展示明文。渠道 SHALL 支持启用/停用，并在保存时提供"发送测试邮件"验证。

#### Scenario: 配置并测试邮件渠道
- **WHEN** 管理员填写 SMTP 配置与收件人列表后点击"发送测试"
- **THEN** 系统发送一封测试邮件并返回发送成功或失败的具体原因

#### Scenario: 邮件凭据脱敏
- **WHEN** 管理员重新打开邮件渠道配置页
- **THEN** SMTP 密码不以明文展示，留空表示不修改

### Requirement: 聊天机器人通知渠道

系统 SHALL 支持配置聊天机器人通知渠道，面向企业私有部署的聊天软件：包括机器人 webhook 地址、可选的鉴权凭据、消息模板。凭据 SHALL 加密存储且回显脱敏。渠道 SHALL 支持启用/停用，并提供"发送测试消息"验证。消息模板 SHALL 支持变量占位符（仓库、节点号、作者、状态、问题摘要、报告链接），未配置时 SHALL 使用内置默认模板。

#### Scenario: 配置并测试机器人渠道
- **WHEN** 管理员填写企业聊天软件的机器人 webhook 地址后点击"发送测试"
- **THEN** 系统向该地址发送一条测试消息并返回成功或失败的具体原因

#### Scenario: 自定义消息模板
- **WHEN** 管理员将模板配置为"【代码评审】{{repo}} 新节点 {{rev}}（{{author}}）{{status}}"并触发一次评审
- **THEN** 机器人收到的通知内容为占位符替换后的实际文本

#### Scenario: webhook 凭据脱敏
- **WHEN** 管理员重新打开机器人渠道配置页
- **THEN** webhook 地址中的鉴权信息与凭据不以明文展示

### Requirement: 通知触发规则

系统 SHALL 支持配置通知的触发条件：全部完成（成功与失败都通知）、仅失败、仅成功。触发条件 SHALL 对所有渠道统一生效。通知内容 SHALL 至少包含：仓库名、节点标识（SVN revision / Git commit 短号）、上库人员、任务状态、问题数或失败原因摘要、报告查看链接。

#### Scenario: 仅失败通知
- **WHEN** 通知规则配置为"仅失败"，一个评审任务成功完成，另一个失败
- **THEN** 仅失败的那个任务触发通知，成功的不发送

#### Scenario: 通知内容完整
- **WHEN** 任一渠道发送通知
- **THEN** 通知文本包含仓库名、节点号、作者、任务状态与问题摘要或失败原因

### Requirement: 通知失败隔离

通知发送失败 SHALL 不影响评审任务的状态与报告；系统 SHALL 对发送做有限次重试，最终失败时记录通知发送日志（含失败原因），可在 Web 控制台查看。通知发送 SHALL 异步执行，不阻塞任务队列。

#### Scenario: 通知发送失败不影响任务
- **WHEN** 评审任务成功但机器人 webhook 地址不可达
- **THEN** 任务状态仍为"成功"，通知日志记录发送失败及原因，且重试次数用尽后不再发送

#### Scenario: 查看通知日志
- **WHEN** 管理员打开通知日志页面
- **THEN** 能看到每次通知的渠道、对应任务、发送结果与失败原因
