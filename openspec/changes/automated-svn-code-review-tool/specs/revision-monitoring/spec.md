# Spec Delta

## Purpose

自动监控一个或多个 SVN 或 Git 仓库的上库情况：轮询发现新增节点后自动创建评审任务，支持按上库人员、按涉及文件夹/文件路径过滤，保证不重复评审、断线与服务重启后可恢复。

## ADDED Requirements

### Requirement: 轮询发现新增上库节点

系统 SHALL 按用户为每个仓库配置的轮询间隔，周期性查询上库情况：SVN 仓库查询 HEAD revision，Git 仓库 fetch 远端后查询指定分支的最新提交；发现比上次已处理位置更新的节点时，识别出所有新增上库节点。监控规则首次启用时 SHALL 默认从当前最新节点开始处理，避免回溯评审整个仓库历史（是否回溯最近 N 个节点 SHALL 可配置）。

#### Scenario: SVN 发现新节点
- **WHEN** SVN 仓库 HEAD 从 r1000 变为 r1003（中间有 r1001、r1002、r1003 三个提交）
- **THEN** 监控器一次性识别出这三个新增节点，并逐一进入过滤判断

#### Scenario: Git 发现新提交
- **WHEN** 监控的 Git 分支 remote/main 从 commit A 前进到 A..E 共 4 个新提交
- **THEN** 监控器识别出这 4 个提交（按时间正序），并逐一进入过滤判断

#### Scenario: 首次启用监控
- **WHEN** 管理员对历史已有上千提交的仓库首次启用监控，未配置回溯数量
- **THEN** 监控器以当前 HEAD/最新提交为起点，不自动回溯评审历史提交

#### Scenario: 轮询期间仓库不可达
- **WHEN** 轮询时 SVN/Git 服务器暂时不可达
- **THEN** 系统记录该次轮询失败并按原间隔继续下一轮，不丢失任何未处理节点，恢复可达后继续从上次位置处理

### Requirement: 按上库人员过滤

监控规则 SHALL 支持配置"只评审指定上库人员"的人员白名单；人员不在白名单内的提交节点 SHALL 不触发评审。

#### Scenario: 白名单命中
- **WHEN** 监控规则配置人员白名单为 ["zhangsan", "lisi"]，新节点的作者是 zhangsan
- **THEN** 系统为该节点自动创建评审任务

#### Scenario: 白名单未命中
- **WHEN** 监控规则配置人员白名单为 ["zhangsan"]，新节点的作者是 wangwu
- **THEN** 系统不为该节点创建评审任务，但在监控日志中记录该节点被跳过及原因

### Requirement: 按路径过滤

监控规则 SHALL 支持配置"只评审涉及指定文件夹/文件"的路径列表（支持目录前缀匹配）；节点涉及的变更路径与列表无交集时 SHALL 不触发评审。

#### Scenario: 路径命中
- **WHEN** 监控规则配置路径列表为 ["trunk/src/core/"]，新节点修改了 trunk/src/core/engine.cpp
- **THEN** 系统为该节点自动创建评审任务

#### Scenario: 路径未命中
- **WHEN** 监控规则配置路径列表为 ["trunk/src/core/"]，新节点只修改了 docs/readme.md
- **THEN** 系统不为该节点创建评审任务，并在监控日志中记录跳过原因

#### Scenario: 人员与路径过滤组合
- **WHEN** 监控规则同时配置人员白名单 ["zhangsan"] 和路径列表 ["trunk/src/core/"]，新节点的作者或路径任一不满足
- **THEN** 系统不为该节点创建评审任务；只有两者同时满足才触发评审

### Requirement: 监控规则启停与去重

每条监控规则 SHALL 可独立启用/停用。系统 SHALL 保证同一仓库同一节点不因监控而重复创建评审任务。监控触发产生的任务 SHALL 与手动触发的任务在同一队列执行，并遵守同一并发约束。

#### Scenario: 停用监控
- **WHEN** 管理员停用某仓库的监控规则
- **THEN** 轮询停止，新上库节点不再自动创建评审任务

#### Scenario: 不重复评审
- **WHEN** 同一节点被相邻两轮轮询都识别到
- **THEN** 系统只为它创建一次评审任务

### Requirement: 重启恢复

服务重启后，监控器 SHALL 从持久化的处理位置继续，不遗漏重启前未处理的新节点，也不重复处理已评审节点。

#### Scenario: 重启后恢复
- **WHEN** 服务在已处理到某仓库第 N 个节点时异常退出，期间该仓库又新增两个节点，服务重启
- **THEN** 监控器恢复后自动补处理这两个新节点

### Requirement: 监控活动可见

Web 控制台 SHALL 展示每个监控仓库的当前状态：轮询是否正常、最新已处理节点、最近跳过/触发的节点记录及原因。

#### Scenario: 查看监控状态
- **WHEN** 用户打开监控页面
- **THEN** 能看到每个仓库的最近轮询时间、最新节点、已处理到的节点，以及最近节点的触发/跳过记录
