# Spec Delta

## Purpose

提供浏览器端的配置与操作界面：管理 SVN/Git 仓库与凭据、LLM Provider 配置、监控规则、通知渠道，手动触发评审，并查看任务进度与历史报告。

## ADDED Requirements

### Requirement: 仓库管理

Web 控制台 SHALL 支持添加、编辑、删除、启用/禁用仓库配置，类型 SHALL 覆盖 SVN（URL + 用户名/凭据）与 Git（远端 URL、凭据/访问令牌、监控分支）。凭据 SHALL 以非明文形式持久化，且在界面回显时 SHALL 不展示明文。

#### Scenario: 添加仓库并验证连通
- **WHEN** 管理员选择仓库类型并填写对应地址和凭据后点击"保存"
- **THEN** 系统验证仓库连通性（SVN 用 `svn info`，Git 做远端访问验证），验证通过后保存配置；验证失败时提示具体错误且不保存

#### Scenario: 删除仓库
- **WHEN** 管理员删除一个仓库配置，且该仓库存在关联的监控规则或历史报告
- **THEN** 系统提示影响范围并要求确认；确认后停止该仓库的监控，历史报告予以保留

### Requirement: LLM Provider 配置

Web 控制台 SHALL 支持配置评审所用的 LLM Provider（自定义 API 地址、API Key、模型名），该配置用于生成 `ocr` 的 provider 配置。保存时 SHALL 提供连通性测试。

#### Scenario: 配置并测试 Provider
- **WHEN** 管理员填写 API 地址、Key、模型名后点击"测试连接"
- **THEN** 系统对该端点发起连通性验证并显示成功或失败的具体原因

#### Scenario: 凭据脱敏
- **WHEN** 管理员重新打开 Provider 配置页面
- **THEN** API Key 不以明文展示，留空表示不修改

### Requirement: 监控规则配置

Web 控制台 SHALL 支持为每个仓库创建、编辑、启用/停用监控规则，配置项包括轮询间隔、上库人员白名单、路径过滤列表。输入 SHALL 在保存前做格式校验。

#### Scenario: 创建监控规则
- **WHEN** 管理员为仓库 A 配置轮询间隔 5 分钟、人员白名单 ["zhangsan"]、路径列表 ["trunk/src/"] 并保存
- **THEN** 规则启用后系统开始按 5 分钟间隔轮询并应用两个过滤器

#### Scenario: 非法输入校验
- **WHEN** 管理员输入轮询间隔为 0 或负数
- **THEN** 保存被拒绝并提示有效范围

### Requirement: 手动触发界面

Web 控制台 SHALL 提供手动触发评审的界面：选择仓库、选择单节点或区间模式、输入 revision 号，并显示触发结果。触发后 SHALL 能跳转到对应任务查看进度。

#### Scenario: 触发后跳转
- **WHEN** 用户提交手动评审表单且参数合法
- **THEN** 系统创建任务并跳转（或提示链接）到该任务的详情页

### Requirement: 任务与报告查看界面

Web 控制台 SHALL 提供评审任务列表（含状态、仓库、revision、作者、触发方式——手动或自动、时间），支持按仓库、revision、作者、状态、触发方式过滤；点击任务 SHALL 展示完整评审报告，报告 SHALL 以可读方式展示问题位置与描述。

#### Scenario: 过滤自动触发的任务
- **WHEN** 用户按触发方式"自动监控"过滤任务列表
- **THEN** 列表只显示由监控规则自动创建的任务

#### Scenario: 查看报告详情
- **WHEN** 用户点击一个成功状态的任务
- **THEN** 展示该节点的评审发现列表，每条含文件、行号、问题描述与建议

### Requirement: 通知渠道配置界面

Web 控制台 SHALL 提供通知渠道管理界面：邮件渠道（SMTP 配置、收件人列表、测试发送）、聊天机器人渠道（webhook 地址、消息模板编辑、测试发送）、触发规则设置（全部完成/仅失败/仅成功），以及通知发送日志查看。凭据 SHALL 脱敏展示。

#### Scenario: 发送测试通知
- **WHEN** 管理员在渠道配置页点击"发送测试"
- **THEN** 系统向该渠道发送测试通知并在界面显示发送结果

#### Scenario: 查看通知日志
- **WHEN** 管理员打开通知日志页面
- **THEN** 能看到每次通知的渠道、对应任务、发送结果与失败原因

### Requirement: 操作反馈与国际化

Web 控制台 SHALL 以中文为主要界面语言，对保存、删除、启停等操作提供明确的成功/失败反馈。

#### Scenario: 操作失败反馈
- **WHEN** 用户执行的操作因服务端错误失败
- **THEN** 界面展示明确的失败提示，而不是静默失败
